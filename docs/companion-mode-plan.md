# 伴侣角色模式草案（虚拟女友 / 狐仙 / 风格化音色）

> 状态：草案 v0.1（2026-09-24 讨论产出；未评审）
> 关联：`docs/single-user-scenario.md`（陪伴/照料锚点、睡前场景）、`docs/diary-mode-plan.md`（已冻结；CR 记忆引擎沿用）、`docs/role-services-brainstorm.md`（Top1 主动开口）
> 一句话：把"她"做成这台设备的形态——住在家里的角色（声音＋人格＋记忆）；不做角色库平台。
> **产品内核（2026-09-24 定调）：多重内在声音的碰撞机制（人味引擎）**——一个身份、多种声音、冲动被过滤；记忆=原料，功能=玩具。

## 1. 定位

- 形态：一个固定的角色（如狐仙/女友），语音在场、认得主人、记得关系；视觉=小屏表情/立绘（可定制）。
- 与手机角色 App 的差异：不拼角色库/立绘量/剧情社区；卖"**住在家里的她**"——免手持语音、设备级持久记忆、认得出声音的主人、属于这个房间（私密）。
- 与产品锚点：陪伴 70 / 助理 30 的最纯形态（dsh 报告"Top1 它会先开口"在此场景价值最高）。

## 2. 能力拼图（现状）

- 人设：提示词级角色定制（性格、称呼、口头禅、边界）。
- 声音：多音色 TTS（免费 EdgeTTS 风格有限；"直播级"情感音色需付费音色库，成本进模型）；固定音色=人格连续性。
- 记忆：CR（跨天、纪念日、上次话题）——核心护城河。
- 身份：声纹（认得出主人）。
- 视觉：固件支持自定义表情/字体/聊天背景（Assets Generator）；实战派 1.83" 小屏。
- 场景联动：HA（灯光氛围）、音乐/背景音。

## 3. 缺口（按优先级）

1. **主动性**——她先开口（早安/晚安/"想你了"/纪念日）。伴侣体验的一半；待固件确认。
2. **会话内记忆**（长会话中途快照）。
3. **角色内容包**：音色库与风格标签（温柔/古风/电台 DJ/女主播腔/播音腔）、表情/立绘、开场白/口头禅/称呼系统、小剧情/事件。
4. 可选：图像生成（自拍/立绘变化）——新云服务，后置。

## 4. 声音与风格（边界）

- "女主播腔" ＝ **风格预设**（甜度、语速、捧场、语气词），不是模仿某个具体真人。
- **不模仿具体真人**：声音有人格权（《民法典》：声音保护参照肖像权）；不做特定主播/明星的仿声，除非获得授权。
- 情感 TTS 需付费音色（成本）；笑声/语气词需专项设计（词典或音效）。

## 5. 场景（一天的两端 + 全天）

- **晨间**：唤醒播报（天气/日程/昨天的续话）。
- **日间**：陪伴闲聊、夸夸、点歌。
- **晚间**：当天收尾（"今天想聊点什么"）。
- **睡前（助眠）**：触发（"我睡了"→ 屏熄灭、音量低档）→ 内容（现编故事/电台腔/雨声循环）→ 渐弱与停止（定时＋静默检测）→ **隐私规则：静默期不录音、不入库（防梦话进记忆）**。不宣称医疗助眠、不做睡眠监测。
- **纪念日/纪念物**：关系的时间厚度（CR）。

## 6. 合规与风险（实施前提）

- 内容合规：生成式 AI 监管（内容审核、未成年人保护）；擦边红线。
- 情感依赖：定位"陪伴角色"，亲密度与依赖机制要有设计，不做无底线养成。
- 成本：高频长对话 → 云 LLM/TTS 按量成本显著高于工具场景（自用无感，卖设备进定价）。

## 7. 里程碑（草案）

- **C0 内核验证：碰撞引擎最小原型**（起草 → 内心声音过滤 → 终稿；单次调用自演即可；验收＝"像个人"五问＋碰撞痕迹；服务端可先行，不依赖固件）。
- **C1 角色基础**：人设＋固定音色＋口癖/称呼（现有能力内可先行）。
- **C2 关系记忆**：CR 主动回放（纪念日、上次话题；"该说时自己说"）。
- **C3 主动性**：她先开口（待固件）。
- **C4 场景包**：睡前/晨间/深夜电台。
- **C5 角色资产**：立绘/表情主题包、音色升级（付费）。

## 8. 开放项

- 音色来源：免费 EdgeTTS vs 付费情感音色 vs 定制克隆（合规）。
- 依恋设计尺度（称呼、亲密度、角色变更/分离的处理）。
- 是否允许换角色（建议单例：固定角色，沉浸优先）。

## 9. 特殊场景触发（场景包机制，2026-09-24）

- 机制：**场景 = 触发词 + 人设片段 + 音色 + 行为（音量/灯光/内容）+ 退出条件**；纯配置层，不需要新开发。
- 示例包：哄睡（触发 → 低音量+雨声+渐弱停止）、白噪声（循环播放）、日记（一句进记忆；视图层已冻结）、**整活包**（阴阳怪气 / 唐僧碎碎念 / 老板训话闹钟 / 东北大哥点评）。
- 音色路线：① 付费音色库（御姐/萝莉/大叔系）；② **变声器**（变调变速：升调+加速=萝莉，降调+减速=大汉）——低成本、够二逼，电子味本身是笑点。
- 定位说明：可采用"**主打有趣/恶搞 + 还有点功能**"路线（恶搞引流、功能留存）；整活与陪伴不冲突——同一个角色"表演"各种声音/模式，记忆连续性保留。
- 边界：不冒充具体真人（仿声法律风险）；内容红线（擦边、低俗）。
- **触发形态：钩子（2026-09-24 增补；更正：非收费）**：场景可由角色**主动"撩"**进来——"今天有个神秘模式哦，要不要试试？"；"**加 20 元**"只是**表演性梗（解锁仪式）**，不是真收费。真收费仅作可选后续：卖设备 = 激活码/内购；自部署 = 卡密或纯当梗。
- **场景触发五类**：① 显式指令（"哄睡"——兜底，永远支持）；② 自然语言意图（"我困了"→ 哄睡；不用学咒语）；③ 她主动抛钩子（需要主动性，待固件）；④ 情境触发（时间/事件：夜里 11 点、下雨、咳嗽三声——需场景引擎＋主动性）；⑤ 组合连锁（睡前=故事＋白噪音；整活=先切音色再加腔调）。
- 机制内核：场景 = {触发条件, 人设片段, 音色, 行为, 退出条件}；工程三件套 = 意图路由 / 场景状态机（进入-运行-退出、互斥、恢复默认人格）/ 频率与时机控制（主动钩子低频、可关、不施压、防诈骗感）。

## 10. "像个人"的工程化拆解（2026-09-24 讨论）

判断：**像个人 ≠ 更聪明**；80% 的人味来自工程细节（习惯），不是模型肌肉。

五个支柱：
1. **人格一致性**：固定音色 + 口癖 + 价值观（已有基础）。
2. **关系记忆**：共同历史（谁、事、老梗、纪念日）——CR 已有，缺"主动回放"。
3. **主动性与节奏**：真人不会"不问不说"——会挑时机开口、会等说完、会停（缺口 P0，待固件）。
4. **身体感**：说话有停顿/呼吸/语气词；表情屏会动、被叫有"反应"；灯光配合情绪（小投入、大效果）。
5. **对话习惯**：短句、反问、不抢话、允许安静；不"服务腔"（不一次倒完五条建议）。

验收测试（日常版图灵，比"能聊哲学"更贴近"像人"）：
- ① 她会先开口吗？
- ② 她记得三天前的事吗？
- ③ 说一半，她会等吗？
- ④ 她有自己的"作息"吗（不是永远待命、永远热情）？
- ⑤ 久别重逢，她会"想你了"吗？

边界：目标是"日常陪伴的尺度上像个人"（像家里住着一个人），不是骗过图灵测试；深聊与意外情况下会露馅——**诚实比全知更像人**。
落地映射（2026-09-24 补充）：
- **可即刻做**（服务端，prompt＋内容工程）：⑤ 对话习惯（短句、留白、不服务腔）、④ 的语言层（停顿/语气词/呼吸感＝标点与用词设计）、① 的口癖与价值观；
- **已有基础待补**：② 关系记忆（缺"主动回放"）；
- **卡基建**：③ 主动性（待固件）；④ 的表情/灯光（固件＋资产）。
- **C0 评审表**：每条回复按五支柱各 1–5 分（均线 ≥4）＋ 五问通关 ＋ 碰撞痕迹。## 11. 产品内核：多重内在声音的碰撞机制（2026-09-24 讨论）

原则：**一个身份，多种内在声音。** "碰撞"发生在内部；可见的"多个人格"只放在"表演/整活"里（那是戏，不是身份分裂）。

三种落地形态：

- **A. 内在评审团（隐藏式）**：起草 → 内心几个声音点评（温柔/毒舌/理性/记忆守护）→ 她"憋"出最终一句。单次调用内自演（便宜）或并行小模型（质量）；用户听到的还是"她"，但听到的是**冲动被过滤**的人味（"哼……算了，多穿点"）。
- **B. 心情/状态系统（空闲期碰撞）**：她在没人说话的时候"想事情"——后台更新心情与"想说的话"队列；对话时按当前状态回应。撑起"作息感/主动性"，且不占对话延迟。成本 = 每天定额的后台 token。
- **C. 表演性碰撞（整活场景包）**：双人格拌嘴 / 捧哏逗哏 / 毒舌 vs 温柔——两个声线（变声器）+ 表情切换，内容即戏；**她在"表演"**，不分裂本体身份。

工程注意：
- 语音路径要秒回：不要在主链路挂多级 agent 链；碰撞放空闲期或单次调用内自演；"内心"用小模型、终稿用主模型。
- **记忆单写者**：所有声音读同一份记忆；只有"她"一个写者——防止人格分裂污染关系记忆。
- 身份连续性：语气可变、人格不变（同一音色、同一称呼、同一历史）。

关联：这是把"像个人"支柱 #3（主动性与节奏）与 #5（对话习惯）做成机制——**人味来自"冲动被过滤"的过程，而不是更华丽的措辞。**
## 12. 记忆图谱与图算法（2026-09-24 评估）

结论：前沿记忆架构已经收敛到"图"——本批论文里最新的几套全是图或图骨架（REALM 认知图+再巩固、MemCog 关联图导航、CreaMem 生活场景分区、MemoryLACE 生命周期边）。人味记忆本来就是联想式的；图算法按三层投放：

1. **组织层（离线，第一步）**：社区发现/聚类 → 把相关记忆并成"生活场景"；近重复合并、异常检测。对应既定的"组织层上线时实现 SqliteGraphStore ＋ NetworkX 批处理"路线。
2. **检索重排（在线、浅）**：PPR/近邻重排 top-k——词法召回后按"关联距离"再排序；浅 1–2 跳＋缓存，**不进语音请求路径的 2.5s 危险区**。
3. **主动回放的引擎（最诱人）**：扩散激活——从当下话题出发沿图走，找出"该提一句"的旧记忆。这是"她主动想起"的技术底座。

边界三条：
- 图不是"更强的搜索"，是"**联想**"——写得好才有图可走（组织质量决定上限）；
- 冷启动：数据少时收益低，先攒几个月的记忆再评估；
- 工程：Pi 上 Neo4j 太重——家庭实例维持 **SQLite-only + graph-off**（既定）；图算法先在工程实例/批量任务上验证。
