# 单人场景定义（产品锚点）

> 目的：把产品边界固定为**一个人**；后续功能取舍、验收口径以本文为准。
> 关联：`docs/singleton-mode-plan.md`（技术形态）、`docs/voiceprint-integration.md`（身份）、Context Recall 记忆（plan §4）。

## 0. 一句话

一个住在家里的私人终端：**认得我、记得我、替我照料小事**。
它不需要"会很多"，它需要"一直在"。

## 1. 为什么必须锁定单人

| 事实（已核实） | 推论 |
|---|---|
| 单路语音、串行会话：一台设备=一路麦克风，ASR 靠 VAD 切句，TTS 独占输出，"打断"只实现为用户打断助手 | 多人同时说话在形态上不成立 |
| 记忆按 workspace/role 隔离、不按人隔离；声纹/人脸只"告知身份"，不做授权 | 多人共用=管理问题（身份→隔离→权限，三层都缺） |
| 麦克风常开 + 长期记忆 + 云端 ASR/LLM | 只在私人空间成立；公共空间应降级为"无记忆" |

→ **多人场景全部冻结**（不在本阶段设计范围内）。

## 2. 三条锚点（有机整体的骨架）

1. **在场**：固定在一个角落（书桌/床头/厨房）；唤醒即响应，交互成本低于掏手机。
2. **连续性**：同一身份（只有我）+ 同一人格（角色/音色稳定）+ 跨天记忆（CR）——三者叠加才是"一个整体"。
3. **照料**：工具只为照顾我（提醒、音乐、记录、灯光），**不做能力展示**。

动人的东西只可能来自这三处：**它认得我、它记得我、它让我少做一件事。**

## 3. 一天的时间线（场景是否成立的检验表）

| 时段 | 场景 | 依赖能力 | 现状 |
|---|---|---|---|
| 早晨 | 唤醒后不是"你好"，而是"昨天你说面试…怎么样了" + 今天天气/日程 | CR 召回 + 日程数据 | 召回已有；日程缺 |
| 白天 | 碎片捕获（"记一下…"）；提醒；背景音 | 捕获入 CR / 定时器 / 音乐 | 音乐有；捕获、提醒缺 |
| 晚上 | 回家续接白天的话题（同一次会话内） | 长会话中途快照 | 缺（已定案未实现） |
| 睡前 | 收尾：今天聊的写进记忆 + 关灯/放雨声 | CR 保存 + HA | 保存有；HA 待接 |
| 周/月 | "你上个月说的那件事怎么样了" | 关系的时间厚度 | 已有（CR） |
| 任意时刻 | 主动开口：该吃药了 / 下雨了记得收衣服 | 服务端**主动**发起语音 | 缺（需固件确认） |

## 4. 反场景（明确不做）

- 多人共用、会议、公共空间
- 开发者工具箱（`filesystem` / `playwright` / `windows-cli` 只作调试，不进产品叙事）
- 无屏幕设备上的复杂配置（配网/唤醒词必须"触摸几下就会"）
- 为炫技而接的能力（每接一个都要能落进 §3 的时间线）

## 5. 能力映射

**已有**：CR 长期记忆、角色与音色、声纹/人脸（识别能力）、Home Assistant、音乐/天气/新闻/时间、视觉拍照、单例模式（本地部署 + 隐私）。

**要补（按价值排序）**：

1. **主动性**——当前只有唤醒后才响应；单人场景的情绪价值一半来自"它先开口"。需定时任务 + 服务端主动送 TTS（**待固件确认**是否接受非会话期音频）。
2. **会话内记忆**（长会话中途快照）——让"今天上午说的"在晚上有效。
3. **一句话捕获**（"记一下…" → 本地存 → 进 CR）。
4. **记忆可回看/可删除**——信任感来源；CR 目前 additive 无删除，需状态化"遗忘"。
5. **单人身份**（声纹认出主人）——可选，不阻塞主线。

## 6. 待定（拍板项）

- **形态**：固定摆放（推荐：供电稳定、麦克风与唤醒更可靠）vs 随身（电池 + 4G + 降噪，另一套工程）。
- **定位权重**：陪伴 / 助理的建议比例（建议 70/30：先做陪伴，再做助理）。
