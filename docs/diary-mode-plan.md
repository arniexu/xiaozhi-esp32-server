# 日记模式草案（电子日记 × 小智 × Context Recall）

> 状态：草案 v0.1（2026-09-24 讨论产出；未评审）
> ⚠️ 2026-09-24 晚更新：**用户判定不需要**（"完全可以打开手机、用手机输入法记录"）→ 视图层 / 治理层**冻结为参考、不推进**；**CR 记忆引擎保留**（转向服务陪伴/记忆场景，见 Continuity 同日记录）。
> 关联：`docs/single-user-scenario.md`（缺口 ③ 一句话捕获 / ④ 记忆回看删除）、`docs/singleton-mode-plan.md`（CR 集成）、`docs/role-services-brainstorm.md`
> 一句话：把日记做成 **CR 记忆体的用户可见形态**——不做第二套存储；日记 = 捕获层 + 视图层 + 治理层。

## 1. 定位

- 形态：说一句 → 当天沉淀成一条 → 可回看、可删改 → 重要日子它主动提（"去年今天……"）。
- 为什么合身：
  - 记录成本最低：语音随口一句，不掏手机不打字（日记最大的敌人是"懒得写"）；
  - 容器现成：CR 为"个人、私密、跨天"设计（证据链 turns + 组织节点 + 本地存储）；
  - 让隐形记忆变成可见可管：解决"记忆不可见、不可删"的信任问题；
  - 与三锚点一致：在场 / 连续性 / 照料；豆包类 App 给不了"住在家里替人记日子"。
- **与"电脑上敲字/记事本"的区别**：编辑体验电脑更强（不争）；差异在**采集与召回**——现场零摩擦采集（日记真正的敌人不是打字慢，而是"以后写"永远不会发生）、对话内召回（"上次你说…"）、主动提醒（"明天记得修水管""去年今天"）；身份与归属也不同（声纹验证＋本地存储 vs 谁开电脑谁看）。整理可导出回电脑（Markdown/Obsidian）二次打理。（"电脑语音输入法"同理：只是更好的键盘——没有常驻唤醒、没有对话召回、不会开口；设备卖的不是输入能力，是"现场＋记忆回路"。形式上，"房间里常驻的语音终端"才是必需，专用小盒子只是最便宜的载体。）

### 形态速写（使用中的样子，2026-09-24）

三个界面 = **说 / 问 / 看**：

- **说（语音，对应 V1）**：随手"记一下……" → 短回执（"好，记下了"，不展开、不点评）；条目自动带时间；改/删针对"刚才那条"。
- **问（语音回看）**："上周三我记了什么？""去年今天呢？" → 读出来；重要日子可主动提（开关可选）。与通用 App 的关键差异：日记会"开口讲出来"。
- **看（网页 `/diary`，对应 V2）**：手机浏览器打开 Pi 地址；单列按天分组，每条一行（时间 + 一句话），点开编辑/删除（先软删）；顶部搜索与导出。
- 一天的流：白天随手记 → 晚间可选"今天还有要记的吗"（M4，待固件）→ 睡前/次日回看。**安静原则**：不打卡、不点评、不社交。

```
┌─────────────────────────────┐
│ 日记              搜索   导出 │
├─────────────────────────────┤
│ 9月24日 周四                  │
│  08:12  妈复查结果不错         │
│  14:30  买化肥 320            │
│  21:05  明天记得修水管         │
│ ───────────────────────────  │
│ 9月23日 周三                  │
│  09:40  试了新馆子，还行       │
└─────────────────────────────┘
```

- **条目形态（数据）**：时间戳 + 一句话原文（可编辑）+ 可选标签（账/提醒…）+ 状态（正常/已删）；一天一个日摘要（组织层生成，可关闭）。

## 2. 与现有系统的关系（复用，不新建）

- **捕获层（新增）**：关键词/意图"记一下……" → 即时成为带日期标签的候选记忆。
  - 实现先例：审批链路 M1 的 `receiveAudioHandle` 关键词拦截（commit f0c002b）——纯服务端，不依赖固件。
- **组织层（复用）**：会话结束 organizer（≥3 轮）→ 快照 → `POST /v1/import/extension`。
  - 日记条目 = 带 `diary` 标签/kind 的节点 + 每日摘要节点；`evidenceTurnIds` 必填（可检索门槛）。
- **视图层（新增，渠道待拍板——2026-09-24 讨论）**：候选=①局域网网页（Pi 8003，最省成本、免安装、最私密；默认）②触摸大屏 Kiosk（未来在屏上跑同一页面）③手机 App（成本最高）。日常速览可落在设备屏（实战派小屏；未来触摸板）。微信仅评估为"无内容提醒"信道（内容过腾讯+主体审核，不适合做主界面）。
- **治理层（新增，硬要求）**：导出、删除、修改（见 §3）。

## 3. 治理层规格（信任层）

- **修改级别（建议，2026-09-24 讨论）**——修改深度由"主存在哪"决定：**日记条目 = 本地主存（source of truth），CR = 派生检索层**（与"本地保留 raw turns 作证据源"的既有设计一致）。
  - **V1 条目级（必须，语音）**：补记（"再补一句"）、重录（"刚才那条重说"）、删除（"删掉刚才那条"）、小纠错（"把 XX 改成 YY"）。语音修改 v1 只定位"今天/最近一条"；跨天条目走页面。破坏性操作读回确认。
  - **V2 管理级（必须，大屏面）**：目标形态=**可视浏览＋取件信道**；兜底输入优先用**手机系统语音输入法（口述，"看+说"）**，纯打字仅保留"不想出声"场景（家里有人/夜里），不作主路径。实现候选=局域网网页（默认）/触摸大屏 Kiosk。编辑以"重录＋片段口述修正"为主；批量/导出=语音触发＋确认。（2026-09-24 修正：语音优先原则下，键盘不是必需品；兜底输入用语音输入法。）
  - **V3 派生级（信任闭环，可后置但不可省）**：纠正"它记住的内容"——修正/删除摘要与知识节点（旧节点 superseded + 重新组织），确保改过原文后它不再拿旧结论说事。
  - **传播规则**：任一修改 = 主存更新 → CR 派生同步（旧节点 superseded、新节点写入）→ 检索/注入立即以新版本为准。
  - **v1 不做**：版本历史（git 式回滚）、协同编辑、音频编辑（只存文本，音频留存后置）。
- **身份门槛（硬要求，2026-09-24）——本人才能操作**：读 / 写 / 改 / 删全部需验证。
  - 设备侧：**声纹判定**（现状仅"提示"且未启用——`config.yaml` 的 `voiceprint` 段 URL 为空即禁用；需升级为"通过/拒绝"判定，阈值收紧、临界值可要求口令）；可选人脸（实战派带摄像头）作二次确认。
  - 网页侧：密码 + 会话（仅局域网；不用 URL token；导出同样受控）。
  - 未通过 = **不执行、不透露**（连"有没有这条"都不确认）。
  - 威胁模型 = 家人/访客（非专业攻击者）；物理接触 Pi = 信任根，超出应用层防护。
- **删除**（三层覆盖；先软删可恢复，彻底删除走页面二次确认）：
  1. 本地 raw turns：可直接删；
  2. CR 节点：additive 限制 → 状态化 superseded；彻底删除需 CR 侧硬删端点或重建 workspace（开放项）；
  3. 图谱实体（若启用 Neo4j）：已有清理脚本先例。
- **导出**：Markdown（按天）、JSON（全量）；PDF/打印走浏览器打印；**导出目标可对接 Obsidian vault**（按天文件 → 同步进笔记库，整理在电脑完成）——小智=现场采集器，Obsidian=整理台，上下游而非替代。
- 原则：**凡写入可回看、可修改、可删除——否则不写。**

## 4. 隐私口径（2026-09-24 决定）

- 组织层**暂用云端 LLM**（用户决断；理由：只处理不存储）。
  - 注记：处理即出境——选型时优先"不用于训练 / 最短留存"条款与账户设置；复核触发点=本地模型可用性达标等。
- 存储：CR 本地实例（Pi）；raw turns 本地。

## 5. 相邻能力（筛选与结论）

总纪律：每个新能力过三问（无手机时刻？长期关系？家系统/本地？）并落进"一天时间线"（`single-user-scenario.md` 反场景纪律：不做工具箱、不为炫技）。

- **记账（候选，待拍板）**：定位"口头账 / 家里账"——现金、线下、跨渠道的语音即记 + 语音复盘（"上个月买化肥花了多少"）。
  - 不与支付宝正面竞争：支付宝的自动账=数字支付流水；现金/线下仍需手动记，而"打开 App、点账本、打字"正是它做不好的部分。
  - 实现：结构化小库（金额/分类/日期）+ 查询模板；CR 只做回忆辅助。
  - 面向数字支付为主的人群价值低，不抢。
- **打印机（不建议直连）**：需求本质是"数据能带走、能落到纸上"→ 导出 + 网页打印覆盖；直连打印机需处理配网/协议/兼容性，违反"触摸几下就会"原则。后置待明确付费场景。

## 6. 里程碑（草案）

- **M1 一句话捕获**："记一下……" → 打标节点入 CR（服务端可先行）。
- **M2 回看与导出**：`/diary` 页面（8003）+ Markdown/JSON 导出。
- **M3 治理**：删除（三层）+ 修改（语音/页面）。
- **M4 主动收尾**："今天有什么要记的吗"（依赖主动性/固件确认）。
- 自用（Pi）先行：既是狗粮，也是检验记忆质量最直接的镜子。

## 7. 开放项

- 日记条目存储形态（kind/tag 方案）与注入策略（避免与个人记忆抢注入位）。
- 删除硬语义：CR 侧是否加硬删端点。
- 本地条目主存的形态（扩展现有 raw/outbox 结构 vs 轻量结构化小表）。
- 记账是否立项、与日记共用捕获入口的方案。
- 云端组织层复核时点。
- 设备端查看形态（2026-09-24 讨论）：终端＝立创实战派（自带小屏＋摄像头，固件官方支持板）→ 可排"只读日记屏"（需固件 UI + 服务端只读接口；编辑仍回手机/语音）；"合并盒"（Pi 同盒驱动屏跑 `/diary`，kiosk）保留为更大屏产品化候选。屏上隐私要求=默认隐藏、本人验证后才显示；合并盒路线将连带决定"固定摆放 vs 随身"。
- 声纹阈值调参与二次确认（口令/人脸）取舍——需真机实测误拒/误受；当前声纹未启用（URL 未配置即禁用）。
- 界面渠道拍板（2026-09-24 讨论）："无网页"是否成立——日常（记/问/看今天）＝语音+设备屏可覆盖；管理面（V2）落点候选=局域网网页（默认）/触摸大屏 Kiosk/手机 App；微信仅当"无内容提醒"信道；需确认实战派屏是否触摸（决定设备屏承担多少）。
